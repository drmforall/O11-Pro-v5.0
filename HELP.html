Install & sign in

Extract the complete Linux x86-64 release ZIP. On Ubuntu/Debian, install the prerequisites and run the installer:

sudo apt install python3 ffmpeg
sudo bash install.sh

The installer requires systemd, verifies package checksums, asks for an admin username and a password of at least 12 characters, and prompts for an available port. Password entry is hidden. There is no shared default password.

Open http://localhost:YOUR_PORT/login. Use the credentials you created. The installed server listens on loopback; remote access requires an HTTPS reverse proxy. WSL must have systemd enabled.

Navigate your workspace

  • Providers: add and configure stream sources. Import and backup actions manage provider configuration.
  • Monitoring: inspect bandwidth, running streams, connected clients, CPU, and memory. Switch tabs to inspect current activity.
  • Users: manage users, provider access, and permissions. Grant administrative access only when needed.
  • Servers: configure server connections and test connection settings before saving.
  • Jobs: configure scripts, parameters, timeouts, and schedules.
  • Logs: inspect operational messages. Export relevant logs when troubleshooting; remove credentials and tokens before sharing.

Stream & player checklist

  1. Configure a provider and a valid stream source you are authorized to access.
  2. Confirm the source is reachable and any required credentials are correct.
  3. Start the stream and open the available player or playlist.
  4. Check Monitoring for running-stream and bandwidth activity.
  5. If playback fails, inspect Logs and verify codec/container support in the player.

FFmpeg must be available to the service. Playback cannot be confirmed in an empty workspace. DRM playback additionally depends on the source, authorization, browser/player support, and required license configuration; the interface alone does not guarantee compatibility.

Service, configuration & maintenance

sudo systemctl status o11v5
sudo journalctl -u o11v5 -n 50 --no-pager
sudo systemctl restart o11v5

Restarting interrupts active streams. Installed data and configuration live in /var/lib/o11v5; the executable is /opt/o11v5/o11pro-v5. Credentials are stored in the root-only file /etc/o11v5.env. Back up configuration before changing it.

Completed live HLS cache

sudo python3 tools/stream_cleanup.py --root /var/lib/o11v5/hls/live

Run from the extracted release directory to preview cleanup. Add --apply to delete eligible files. All playlists in a group must contain #EXT-X-ENDLIST; open or recently used files are protected for a 120-second grace period. VOD, replay, recordings, and unmarked abandoned streams are excluded.

Memory observation

The optional memory guard records resident memory and flags usage above 1536 MB sustained for 300 seconds. Restart mode is opt-in and interrupts streams. The supplied script targets service o11pro; adapt that service reference to o11v5 for the installed release. It observes excessive usage rather than repairing internal backend code. The installer does not automatically schedule either Python utility.

Troubleshooting

Axios network error

Check service status and Logs. Brief restarts interrupt requests; retry when the service is ready. Confirm the configured server URL and port. A continuing error needs the failed action and corresponding server logs.

Cannot sign in

Use your installer-created credentials. Confirm you opened the correct host and port. There is no universal default password. An administrator can review the protected credentials file locally; never post it in support messages.

Port is already in use

Choose another port during installation or stop the existing instance. The installer refuses to overwrite an existing installation.

Player is blank or buffering

Confirm the stream is running, inspect source errors, verify FFmpeg availability, and check player codec support. Test with a known working authorized source. Monitoring activity alone does not prove successful audio/video playback.

Temporary files remain

Cleanup preserves active files and playlists without an explicit completion marker. Check the configured cleanup path and scheduling. Do not delete the entire cache while streams are active.
